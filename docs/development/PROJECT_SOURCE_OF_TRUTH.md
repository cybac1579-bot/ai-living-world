# AI Living World — 개발 기준·변경 통제·인계 정본

작성: 2026-11-23
목적: 대화창, 자동 개발, 수동 개발이 바뀌어도 방향을 잃지 않도록 하는 단일 진입점.
이 문서는 기존 사용자 확정 설정을 대체하지 않고 **참조·검증 순서**를 고정한다.

## 매 작업 시작 전 필수 순서
1. GitHub `main` 최신 HEAD와 최근 커밋을 조회한다. 다른 프로젝트와 혼동하지 않는다.
2. 이 문서와 아래 링크의 **실제 최신 내용**을 읽는다. 과거 대화 기억/요약만으로 작업하지 않는다.
3. 마지막 변경 사항·테스트 상태·현재 차단 문제를 확인하고 중복/충돌 작업을 피한다.
4. 1차 플레이본에 직접 필요한 작업을 우선한다. 독립 실험 모듈만 무한히 확장하지 않는다.
5. 구현 후 테스트 실행 결과(통과/실패/미실행), 변경 커밋, 남은 장애를 분리해 기록한다.
6. 세계의 중요한 사용자 확정 변경은 해당 정본 문서 및 Google Drive 세계관 기록에 반영하고 재조회한다.

## 절대 바꾸지 않는 개발 방향 (사용자 확정)
- Android 세로형 비주얼 노벨/생활 세계를 실제 플레이 가능하게 구현한다. 단순한 대화형 기획서나 독립 Python 데모가 최종 목표가 아니다.
- 플레이어의 행동·말·감정·출신·이동을 AI가 임의로 결정하지 않는다.
- 게임 종료 중 세계 시간이 정지한다. 게임 내 시간 진행 시 NPC는 플레이어와 무관하게 생활한다.
- 라나와의 만남, 연애, 결혼은 강제 이벤트가 아니다. 결혼 후에도 생활이 계속된다.
- 장기 관계(약 1년 규모의 일관성)와 추후 복수 관계/하렘 루트를 막지 않는 확장형 구조. 어떤 NPC의 동의도 미리 가정하지 않는다.
- 주요 인물/필수 시설 NPC만 필요한 깊이로 설정한다. 기타 주민에게 상세 캐릭터 시트·일러스트를 강제하지 않는다.
- 첫 구현은 브레나와 라나 중심. 외부 지역 출입 금지를 세계관으로 확정하지 않는다.
- NPC 대사에는 화자 이름과 은은한 색 배경의 대화창. 레티시아의 대화창은 연한 파랑. 상황 묘사와 대사를 구분한다.
- 새 주요 인물·지역·전투·사건·큰 외형/감정 변화에서 일러스트 필요성을 확인한다. 승인된 이미지가 실제 저장/게임 삽입됐는지 별도로 검증한다.
- 온라인 로그인/GPT 기능은 보안 검증 전 Android 디버그 빌드에서 비활성화한다.

## 2026-11-25 사용자 인계 반영

게임 플레이 중 남는 ChatGPT Plus 구독 사용량으로 온라인 대화와 세계 진행을 구동하는 것이 프로젝트의 목적이다. 별도 종량제 API로 전환하려면 사용자와 방향을 다시 확인한다. 현재 오프라인 디버그 모드는 입력·기억·화면을 검증하는 임시 환경이다. Android 구독 연동은 공식 지원 범위, 인증 및 사용량 귀속을 확인한 후 실제 한 턴으로 검증한다.

1차 플레이본의 리소스 기준은 라나 고유 경험 90%, 공통 기반 10%다. 라나의 외형·의상·창은 [승인 시트](https://docs.google.com/document/d/1WkerhNomVGJa_0rXIv-GstLBogOKpGrnSqImEzducIg/edit)를 따르고, 그림체·조명·감정 표현의 품질은 [레티시아 기준 이미지](https://docs.google.com/document/d/11xoNt4QdF_ebXFpkM01R-wF8Z9RbvRQwtJWWG0xYaG8/edit)를 참조한다. 외부에서 준비한 이미지는 APK 포함과 실제 장면 표시까지 별도로 검증한다.

이전 자동·수동 병행 지침은 운영 이력이다. 현재는 Work 수동 개발을 진행하며 시간제 자동 개발 복구는 보류한다. 세계 시간, 플레이어 선택권, 결혼 이후 생활 및 첫 20~30분 수용 기준은 위 정본을 따른다.


## 2026-11-25 사용량 효율 운영 원칙 (사용자 승인)

- 실제 코드 수정, 테스트, 오류 해결, 배포 및 에셋 통합은 Work에서 진행한다.
- 기획, 세계관 설정, 일러스트 제작 및 검수는 일반 대화를 우선 활용한다.
- Work 기본 모델은 선택 가능할 경우 Sol Medium을 권장한다. AI가 작업 중요도와 기술 난이도를 판단한다.
- 단순 작업은 경량 모델, 일반 개발은 Sol Medium, 복잡한 개발은 Sol High, 고난도 오류 및 핵심 구조 검증은 Astra를 권장하되 실제 선택 가능 모델에 맞춘다.
- 현재 모델로 충분하면 변경 요청 없이 진행한다. 변경이 필요하면 작업 시작 전에 추천 모델, 추론 수준, 이유를 안내한다. 사용자가 난이도를 직접 판단하도록 요구하지 않는다.
- 사용량 절약을 위해 품질이나 필수 검증을 희생하지 않는다. 모델별 절감 효과는 실제 결과와 사용량으로 검증한다.
- 새 대화에서도 최신 정본을 조회하고 이 원칙을 적용한다.
