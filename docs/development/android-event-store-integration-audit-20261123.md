# Android 원본 엔진 저장 구조 검토 — 2026-11-23

## 실제 확인 근거
GitHub Actions `45083072461`의 `android-source-inventory` 성공 로그에서 ZIP 내부 `world_engine.py` 533–650행과 `vn_server.py` 관련 구간을 직접 확인했다. 원본 ZIP을 변경하지 않았다.

- `EventStore`는 `initial_state.json`, `events.jsonl`, `state.json` 캐시를 사용한다.
- 원본 상태와 저널을 읽고 해시 연결 및 리비전을 검증한 뒤 `transition`을 재실행하여 복원한다.
- 상태 캐시는 원본이 아니며, 캐시 기록 실패는 저널에 이미 확정된 변경을 취소하지 않는다.
- JSON 초기 상태/캐시는 임시 파일 기록·fsync·os.replace를 사용한다.
- 저널 추가는 flush/fsync를 사용하고, 읽기/쓰기에는 파일 잠금을 사용한다.
- `advance_time`은 명시적으로 호출하며 앱 종료 중 경과 시간을 자동 반영하지 않는다.

## 설계 결정 (기술 구현 방침, 사용자 세계관 변경 아님)
1. `prototype/brena_save.py`는 **독립 원형의 검증용**으로만 둔다. 기존 Android `EventStore`를 대체하거나 원본 저장 파일을 이 모듈로 덮어쓰지 않는다.
2. 브레나 세계를 실제 게임에 통합할 때 기존 `EventStore`의 이벤트/전이 모델과 호환되는 방식을 우선 검토한다. 관계/기억/시간을 두 개의 서로 다른 권위 있는 저장소로 나누지 않는다.
3. Android 원본 엔진의 기존 테스트를 압축 해제한 상태에서 CI로 실행하고, 그 결과를 확인한 후 통합 패치를 작성한다.
4. 추가 확인 사항: 저널의 마지막 줄이 부분 기록되었을 때의 복구 정책, 원본 초기 상태 파일의 손상 시 복구, 버전 마이그레이션, 기존 데이터와 브레나 데이터의 정합성. 현재 해결되었다고 주장하지 않는다.
5. 온라인 인증/GPT 연동은 보안 검증 전까지 비활성 상태를 유지한다.
